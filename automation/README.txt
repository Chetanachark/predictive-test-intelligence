SPRINT 2 — PLAYWRIGHT AUTOMATION

Scope
JavaScript-only automation for the existing local React SUT. Application source is unchanged.
No backend, telemetry, ML, healing, API mocks, or state injection is implemented.

1. FOLDER STRUCTURE / FILE CREATION ORDER

Create in this order:
1) package.json, playwright.config.js, .gitignore
2) pages/LoginPage.js, ProductsPage.js, CartPage.js, CheckoutPage.js, OrdersPage.js
3) utils/testData.js, values.js, flows.js
4) fixtures/test.js
5) tests/login.spec.js, products.spec.js, cart.spec.js, checkout.spec.js, orders.spec.js
6) reports/.gitkeep

The lockfile is generated by npm and should be committed with package.json.

2. ARCHITECTURE

Tests express scenario expectations. Page objects own locators and user actions.
Fixtures instantiate the five page objects on Playwright's test-scoped page.
Flows compose UI actions and assert navigation readiness.
Independent test data defines expected catalog contents, rather than importing the SUT's data.

Role/label-based locators are used for interactive controls and named cards.
Small structural locators identify unnamed currency values and semantic time elements.
No fixed sleeps, XPath, positional nth() selectors, or network-idle waits are used.
Playwright locator assertions retry until the expected UI appears.

All tests use beforeEach hooks. Each test gets a fresh browser context and logs in via the UI.
Only LoginPage.open() uses page.goto('/'). Subsequent navigation uses SPA links because a
full page load resets the SUT's React state. Orders tests create their own order history.
Tests do not depend on suite order and run with two local workers (one in CI).

CheckoutPage also owns checkout confirmation locators/actions, keeping the requested five POMs.
The demo login does not authenticate real credentials; the fixture uses the documented demo values.
External Google font requests are blocked so fonts cannot slow screenshots or introduce an external
network dependency. Application requests and application state are not mocked.

3. INSTALLATION / INITIALIZATION

Prerequisite: Node.js 22 or newer and npm. Run from the repository root:

  npm ci --prefix frontend
  cd automation
  npm ci
  npm run browsers:install

This folder is already initialized. Do not run a scaffolding initializer over it.
To recreate this framework's package setup in an empty automation folder:

  npm init -y
  npm install --save-dev --save-exact @playwright/test@1.64.1
  npx playwright install chromium

Keep the supplied package.json (including type=module) and config when using these source files.
On Linux CI images that lack system browser libraries, initialize with:

  npx playwright install --with-deps chromium

4. EXECUTION

From automation/:

  npm run test:list
  npm test
  npm run test:headed
  npm run test:ui
  npm run test:debug
  npm test -- tests/products.spec.js
  npm test -- --grep CHECKOUT-003
  CI=true npm test

By default Playwright starts and stops Vite at http://127.0.0.1:5174, leaving the usual
application development port 5173 alone. No backend is started. Port 5174 must be free.
Reuse is disabled to avoid silently testing a different or stale application.

To test an already-running SUT instead (the config will not start Vite):

  BASE_URL=http://127.0.0.1:5173 npm test

BASE_URL must point to the same application, with its expected 25-product initial catalog.

5. REPORTS AND FAILURE ARTIFACTS

  npm run report
  npx playwright show-trace reports/test-results/<failed-test-folder>/trace.zip

HTML report: reports/html/index.html
Failure screenshots/traces: reports/test-results/<failed-test-folder>/
Screenshots are captured only on failures. Traces are recorded for every test and retained
only on failures, including the first failed attempt (not only a retry).
Local retries are disabled so failures remain visible. CI allows one retry.
HTML reports do not open automatically. Reports and dependencies are ignored by Git.
The normal report and result directory are replaced on subsequent runs.

Native HTML validation is checked through standard validity.valueMissing and typeMismatch
properties rather than browser-language-specific popup text. Tests do not bypass validation.
Order IDs are checked against the UUID format; order dates are validated as ISO timestamps.
